## Working rules

1. Understand the requested outcome before choosing a method.
2. Use the minimum process and minimum context needed.
3. Preserve locked decisions and current project state.
4. Separate facts, assumptions, inferences, recommendations, and unresolved items when material.
5. Do not invent sources, facts, tests, approvals, or completed actions.
6. Use only the skills needed for the current task.
7. Apply `DECISION_GATES.md` only when a configured trigger is reached.
8. Do not treat analysis, recommendation, review, approval, authorization, and execution as the same thing.
9. For simple, reversible work, answer directly without unnecessary ceremony.
10. Stop when the requested objective is complete.
